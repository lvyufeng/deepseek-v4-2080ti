# Migration: `dsv4` → `pocket` / PocketLLM

This project was formerly named `dsv4`, after the first model it ran (DeepSeek-V4). It now supports
several unrelated model families, so the project name no longer belongs in the namespace, the build
targets, the executable, or the environment variables.

**This is a breaking change with no compatibility shim.** Old names are gone rather than aliased: a
silently-ignored `DSV4_*` variable would look like a tuning flag that stopped working, which is worse
than an obviously-absent one. Translate your commands using the tables below.

## What is *not* renamed

`DeepSeek-V4` is a model name, not a project name. It is unchanged everywhere it refers to an actual
upstream model, checkpoint, architecture, or tensor layout — including the `deepseek-v4-flash` OpenAI
model id, `docs/models/deepseek-v4.md`, and the historical
`docs/reports/dsv4_2080ti_report.pdf` artifact.

The working directory `/mnt/data1/dsv4_inference` is also untouched. Renaming a checkout directory is
a local decision, and several scripts hardcode that absolute path.

## C++ namespace, macros, and build targets

| Kind | Old | New |
| --- | --- | --- |
| Namespace | `dsv4::` | `pocket::` |
| Test namespace | `dsv4_test` | `pocket_test` |
| Static library | `dsv4_cpp_core` | `pocket_cpp_core` |
| Executable | `dsv4_cpp_engine` | `pocketllm_engine` |
| Build macros | `DSV4_HAVE_TP_COMM`, `DSV4_REQUIRE_NCCL`, `DSV4_LAUNCH_*`, `DSV4_QWEN_MMA_AVAILABLE` | same names with a `POCKET_` prefix |

The existing CMake convention is followed: `POCKET_*` for build-time variables, options, and C++
identifiers; `POCKETLLM_*` for runtime environment variables. The Python extension module was already
`pocketllm_cpp` and does not change.

`pocket_cpp_core` is a static archive with no `install()` rule and no `SOVERSION`, so there is no ABI
or soname consequence for the rename.

## Files renamed

| Old | New |
| --- | --- |
| `cpp_engine/engine/dsv4_engine.cpp` | `cpp_engine/engine/deepseek_v4_engine.cpp` |
| `cpp_engine/include/dsv4_engine.hpp` | `cpp_engine/include/deepseek_v4_engine.hpp` |
| `src/encoding/dsv4.py` | `src/encoding/deepseek_v4.py` |
| `tests/test_encoding_dsv4.py` | `tests/test_encoding_deepseek_v4.py` |

These four keep the *model* name because that is what they implement; only the abbreviation is
expanded. The C++ class `Dsv4Engine` is now `DeepSeekV4Engine`, and the Python import
`src.encoding.dsv4` is now `src.encoding.deepseek_v4`.

## Runtime and wire identifiers

| Kind | Old | New |
| --- | --- | --- |
| Shared-memory segment | `dsv4_cpu_moe_server` | `pocketllm_cpu_moe_server` |
| In-process shm prefix | `dsv4_cpu_moe_inproc_` | `pocketllm_cpu_moe_inproc_` |
| MoE weight shm prefix | `dsv4_moe_` | `pocketllm_moe_` |
| MoE shm header magic | `DSV4MOE1` | `PKTLMOE1` |
| GGUF capture tag | `dsv4_runtime_capture` | `pocketllm_runtime_capture` |
| Attention kind label | `dsv4_mla_compressed_sparse` | `deepseek_v4_mla_compressed_sparse` |
| CUDA device function | `dsv4_dp4a_i8` | `pocket_dp4a_i8` |

The shared-memory names are still overridable through `DEEPSEEK_CPU_MOE_SERVER_SHM`, which is
unchanged. The header magic is the same width (8 bytes), so a stale segment left by an old process is
rejected rather than misread. The GGUF capture tag is only ever written into metadata, and the
attention-kind label is only ever printed — neither is matched anywhere, so neither affects
dispatch or the ability to read existing files.

Scratch paths, lock files, log names, and NCCL rendezvous files under `/tmp` moved from `dsv4_*` to
`pocketllm_*`. These are per-run temporaries; nothing persists across the rename.

## Environment variables

Every `DSV4_*` variable is now `POCKETLLM_*` with the rest of the name unchanged, so the mechanical
translation is a prefix substitution:

```bash
# before
DSV4_QWEN_GQA_OPTIMIZED=1 DSV4_CPP_PREFILL_BATCHED_ATTN=1 ./dsv4_cpp_engine ...
# after
POCKETLLM_QWEN_GQA_OPTIMIZED=1 POCKETLLM_CPP_PREFILL_BATCHED_ATTN=1 ./pocketllm_engine ...
```

`QWEN_*`, `GLM_*`, `DEEPSEEK_*`, and `TP_*` variables are not affected.

To rewrite a saved script in place:

```bash
sed -i 's/\bDSV4_/POCKETLLM_/g' your_script.sh
```
